# Callnote: следующий интерфейс и нативные модули

В этом изменении реализован интерактивный HTML-макет callnote-v2.html. Запись, загрузка моделей и глобальные горячие клавиши в настольное приложение этим изменением не добавлены.

## Два окна

Главное: расшифровка, позиция на дорожке, источники и копирование. Компактное: начало/остановка, последние фразы, таймер, переход в главное окно, настройки сочетаний. В HTML компактное окно перемещается внутри страницы; в Qt оно должно стать отдельным окном с режимом поверх остальных и сохранением позиции. Закрытие компактного окна не должно останавливать запись. Горячие клавиши глобальные в приложении; в макете — локальные для страницы с сохранением в localStorage и проверкой дубликатов.

## Модели

Источник первого каталога: https://huggingface.co/Systran/models . Совместимые многоязычные tiny/base/small в формате CTranslate2. Импорт по owner/repo либо URL: получить метаданные, показать лицензию и размер, проверить config.json, model.bin и tokenizer.json, закрепить revision, затем загрузить файлы во временную папку с прогрессом/отменой. После проверки загрузки атомарно переместить в каталог моделей. Не исполнять удалённый Python-код. Не выдавать синтаксически корректный repo ID за проверенную модель.

Экспорт: переносимая папка с файлами модели, лицензией и manifest (repo, revision, язык, формат, хэши). Импорт папки проверяет manifest и совместимость движка. Произвольные GGUF, PyTorch и ONNX требуют отдельных адаптеров; они не должны называться совместимыми с faster-whisper автоматически.

## Системный звук

macOS: отдельный нативный модуль ScreenCaptureKit, capturesAudio, исключение аудио Callnote через excludesCurrentProcessAudio. Микрофон отдельным потоком; разрешение на микрофон не заменяет доступ к системному звуку. Доступ к системному звуку проверять до состояния «Запись». Фактическое наличие буферов и уровень сигнала показывать отдельно от разрешения.

Windows: WASAPI loopback для выбранного устройства вывода, микрофон отдельным capture-клиентом. Устройства могут меняться при подключении Bluetooth/наушников. При смене маршрута переподключать поток и показывать разрыв, не продолжать молча со старым устройством. Для нескольких выходных устройств нужен явный выбор/несколько клиентов: один endpoint не равен всему звуку всех устройств.

Источники записывать на независимые дорожки с единой монотонной шкалой времени. Запись на диск отделить от очереди ASR: медленная модель не должна прерывать запись. Для распознавания преобразовывать копии буферов в mono 16 kHz. При объединении учитывать разные частоты, смещение и дрейф часов. Источник «Ваш микрофон» не заменяет диаризацию; в системном звуке может быть несколько собеседников. При записи динамиков возможен повтор речи собеседника через микрофон; нужны раздельные дорожки/эхоподавление.

Не обещать захват «в любом случае»: отказ в разрешении, защищённый звук, эксклюзивный вывод и исчезновение устройства должны иметь видимый статус и понятное восстановление.

Источники: https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/capturesaudio ; https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/excludescurrentprocessaudio ; https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording .

## Приёмка нативной реализации

Zoom и браузерный звонок с наушниками; оба источника отдельно/вместе; смена вывода и микрофона; запрет/отзыв доступа; медленная модель; двухчасовая запись без рассинхронизации; горячие клавиши при фокусе Zoom; перенос модели на компьютер без сети; отмена/повтор оборванной загрузки.
